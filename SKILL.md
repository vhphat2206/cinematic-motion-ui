# Cinematic Motion UI

A page generated by a model usually looks like the average of every page it has seen: a centred
badge, a bold Inter headline, a purple-to-pink glow, two buttons, three icon cards, everything fading
up at the same speed. Nothing is wrong and nothing was decided. People recognise that average
instantly, and that recognition is what "looks AI-made" means.

Gallery-grade pages (the kind sold as premium prompts) differ in four ways, and
this skill is built around them:

1. **One strong visual idea carries the page.** A cinematic image or video, a giant word, a
   character, a generative field. The UI serves it instead of competing with it.
2. **Typography with contrast and care.** A type decision that belongs to this brand (a mega
   wordmark, a condensed grotesk at scale, a high-contrast serif set alone, mono as the voice),
   negative tracking that scales with size, line-height under 1.15 on display type, and sometimes
   kerning adjusted letter by letter.
3. **Choreographed motion.** Every element gets its own entrance type and its own delay, with one
   easing family, so the page *assembles* instead of fading in. The page is still complete and
   readable if no animation ever runs.
4. **Specific values everywhere.** Exact hex, exact px, exact easing, exact copy. Vagueness is how
   defaults (and the AI look) leak in. Premium gallery prompts are 15–40 KB of exact values for one
   screen. That precision is the product.

## Economy mode

If the user asks to save tokens or go fast ("economy", "quick", "cheap", "save tokens", "tiết kiệm",
"làm nhanh", "đỡ tốn token"), keep the same quality bar but cut the expensive parts:

- Read only this file plus the one reference you need most (usually `references/archetypes.md`;
  `references/typography.md` instead if the page is in Vietnamese). Skip the rest.
- Write the direction card in 4–5 lines and skip the full build spec.
- Start from `assets/starter.src.html` and build with `scripts/inline_kit.py`; don't retype the kit.
- Verify with `scripts/audit.py` (it costs almost nothing), then take one screenshot at 1440×900
  and one at 375×812. Fix only what is clearly broken, in one pass. No extra fix-and-look rounds, no
  mid-animation frames, no extra viewport sizes, and no subagents.
- Keep the report to three or four lines.

Say in one line that economy mode is on, so the user knows the page got a lighter check.

## The run

Work through these steps in order. Steps 1–2 are thinking on paper and take a few minutes; skipping
them is the most common reason output drifts back to the average.

### 1. Direction card

Read the project (existing brand, fonts, colours, copy, assets) and the user's brief. Then write a
short direction card in your reply or in a scratch file, using `references/spec-template.md` § Direction card:

- **Subject & audience**: who this is for, in one sentence, in the user's own nouns.
- **Archetype**: pick one of the seven in `references/archetypes.md`. Read that file now; it gives
  each archetype's composition, type, palette, materials and signature motion. If the user names a
  reference (a site, a gallery template), map it to the closest archetype.
- **Three mood words** that are not "modern, clean, sleek" (those describe every page).
- **Palette**: background, ink, muted ink, at most one accent. Name hex values.
- **Type pair**: from `references/typography.md`. Note the role of each face.
- **Moves I'm not using**: name at least two of the "tasteful AI" defaults from
  `references/anti-ai-tells.md` § Second-order tells that this page will avoid, and what replaces
  them. Gallery prompts have been copied so widely that their own recipe is now a tell.
- **Signature moment**: the one thing someone would describe to a friend ("the title letters rise
  while thin rings draw themselves around her face"). If you can't name it, the page will be forgettable.
- **Media plan**: what fills the hero and where it comes from (step 3).

### 2. Spec before code

Fill in the rest of `references/spec-template.md`: tokens, layer stack, markup order, each component
with its states, the motion table (element → entrance type → delay → duration), and the breakpoint
table. Keep it terse. It is a working document, not prose. This is the step that makes the result
precise: once values are written down you implement decisions instead of reaching for defaults.

If the user asked for a *prompt* or *spec* (to paste into another builder) rather than code, the
filled spec is the deliverable. Follow the structure in `references/spec-template.md` § Prompt form.

### 3. Media

The hero image or video does most of the emotional work. Read `references/media.md`, then choose in
this order:

1. Assets the user provided or that exist in the project.
2. A generative background from `assets/backgrounds/` (canvas particle wave, WebGL shader field,
   drawn SVG rings), tuned to the palette. These are real motion, not placeholders.
3. A designed media slot: a styled fallback (gradient field or generative layer) plus a ready-to-use
   generation prompt for the image or video in a comment and in your report, so the user can drop
   the file in.

Never hotlink random stock (`picsum`, `source.unsplash.com`, placeholder services) and never leave
grey boxes. Both are the fastest way to look unfinished.

### 4. Build

- **Single-file HTML** (default when there's no project): start from `assets/starter.src.html`. It
  is plumbing (layer stack, motion kit, failsafes, reduced-motion handling, mobile menu, grain), not
  a look. Restyle and recompose it for the chosen archetype. Keep the `/*@@MOTION_KIT_CSS@@*/`,
  `/*@@MOTION_KIT_JS@@*/` and `/*@@BG:name@@*/` placeholders in your source and produce the final file
  with `python3 <skill>/scripts/inline_kit.py page.src.html index.html`, which inlines the kit
  and backgrounds exactly instead of you retyping them. (`assets/starter.html` is the same starter
  already inlined, for reading.) The `examples/` pages show the quality bar. In blind
  reviews they scored as less AI-looking than the gallery templates they learned from:
  `cinematic-bay-hero.html` (A: timber louvres opening onto a misty bay),
  `dark-code-review-hero.html` (B: the product's own diff is the image, no accent-word trope),
  `light-window-hero.html` (light A/C hybrid: morning sun drifting across a wall in real time). Skim the one closest to your brief for the level of detail and the way one concept
  ties image, type and motion together. Don't copy its composition, copy or palette: each brief
  deserves its own idea.
- **React / Next / Tailwind / Framer Motion**: read `references/react-port.md`. Keep entrance
  animations in CSS keyframes so server-rendered HTML is visible without hydration, and use Framer
  Motion for scroll-linked and interactive motion.
- Motion details: `references/motion.md`. Surfaces: `references/materials.md`. Responsive:
  `references/responsive.md`.
- Inline SVG for every icon and the logo mark, drawn for this brand. Icon fonts and stock icon sets
  in feature rows are a strong template signal.

### 5. Words

Copy is half of why pages read as AI. Rules:

- Use the subject's concrete nouns and verbs ("Train agents on your own runbooks", "Resorts drawn
  from the tide line") instead of category abstractions ("Unlock the power of AI").
- Headlines are 4–9 words split across two lines on purpose; the line break is part of the design.
- No invented proof. Customer logos, testimonials, ratings and business statistics must come from
  the user. If the composition needs a stats row and you have no real numbers, either use
  non-claim facts (location, founding year, number of services offered, opening hours) or mark them
  clearly as placeholders in code comments and in your report.
- Write in the user's language when the page is for their market. Vietnamese copy needs a font
  with full Vietnamese glyph coverage (check `references/typography.md`).
- Avoid the phrases listed in `references/anti-ai-tells.md` § Copy. `scripts/audit.py` flags them.

### 6. Verify. Look at it, then fix it.

Passing checks is not the same as looking good, but failing them guarantees it doesn't.

1. Run the static audit: `python3 <skill>/scripts/audit.py <file-or-dir>`. Fix every HIGH; fix or
   consciously accept every MEDIUM.
2. Open the page in a real browser (built-in browser pane, Playwright, or Chrome, whichever is
   available). Wait ~3 s for the entrance to finish, then run the snippet in
   `scripts/runtime_check.js` through the browser's JS evaluation. It reports text that stays
   hidden, horizontal overflow, text cut off by a one-screen lock, broken media, fonts that didn't
   load, small tap targets and elements that still run animations. Also read the console for errors.
   A hidden or background browser tab renders no frames, so CSS/WAAPI timelines and
   `requestAnimationFrame` loops stall and the page can look blank or half-built in screenshots.
   Before judging, take a screenshot or two (each one renders frames), or run
   `document.getAnimations().forEach(a => { try { a.finish() } catch (e) {} })`, then check again.
   Also strip every `<script>` from a copy of the page and load it once: all text must still be
   visible and the layout intact.
3. Screenshot at **1440×900**, **1280×720** (short laptop: the most common place heroes break) and
   **375×812**. If the page has a mobile menu, open it and screenshot it too.
4. Look at each screenshot and ask the questions in `references/anti-ai-tells.md` § The squint test.
   Fix what fails. Do at least one fix-and-look round even if the first pass looks fine.
5. If you can't open a browser at all, say so in the report. Don't claim visual verification you
   didn't do.

### 7. Report

Tell the user briefly: the direction (archetype, signature moment, type pair), what is placeholder
(media, stats, links) and exactly how to replace it, and what you verified at which sizes.

## Laws that hold across archetypes

Composition
- The hero is one viewport on desktop (`100dvh`, no scroll inside the hero) unless the brief is a
  long landing page. Content anchors to the bottom or to the corners, not to the dead centre. The
  upper part belongs to the media.
- Layer stack, back to front: background colour → media → scrim → page content → grain. The scrim
  is tuned to the media (a radial darkening behind the text, a top gradient behind the nav), so text
  stays readable without boxing it in a card.
- At most two calls to action in the hero: one solid, one ghost or glass. Never three.
- The "badge pill above the headline" and the "three stats in a row at the bottom" are template
  furniture now. Use them only when the content truly is a short label or three real numbers, and
  even then change the form (a single fact, a small table, corner copy, a timeline).
- Use a radius system per archetype (sharp 0–7 px for tech and editorial, pills for soft and
  consumer) and stick to it. Uniform `rounded-2xl` on everything is a template signature.

Typography
- Display sizes: tracking from −0.03em to −0.05em, line-height 0.9–1.12. Small caps and mono
  micro-copy: tracking from +0.04em to +0.12em, uppercase, 11–14 px.
- At most one emphasis device per headline, chosen from the brief. The serif-italic word inside a
  sans headline ("Train *AI agents* on…") is the single most recognisable "tasteful AI" tic of
  2025–26: blind reviewers flag it on sight. Don't use it by default. Prefer scale or weight
  contrast, a deliberate line break, colour, a drawn mark tied to the concept (the ripple from a
  diacritic, a red-pen squiggle under a bug), or no emphasis. If a serif italic really is the
  brand's voice, set the whole line in it rather than one word.

Motion
- One easing family (`cubic-bezier(.16,1,.3,1)` expo-out by default). Entrances last 0.6–1.35 s and
  are staggered from about 0.1 s to about 1.5 s total, in reading order. Each element type gets a
  distinct entrance (mask-rise for headlines, scale for nav pills, wipe for buttons, rise for stats).
- Content is visible at rest. The hidden state lives only in the keyframe's 0% with
  `animation-fill-mode: both`, plus a JS failsafe. A page that stays blank when JS or animations
  fail is broken, however good it looks on the happy path.
- Ambient motion (video, particles, shader) lives in the media layer. Foreground UI is still after
  its entrance, apart from hover feedback (0.2–0.35 s) and optional scroll-linked effects.
- Honour `prefers-reduced-motion`: no entrance, no ambient loop (render one still frame instead).

Materials
- Glass and metal are for one or two controls floating over media, not for every card.
  Recipes are in `references/materials.md`.
- Add grain (6–10 % opacity) over media-heavy pages. It unifies generated imagery with the UI.
